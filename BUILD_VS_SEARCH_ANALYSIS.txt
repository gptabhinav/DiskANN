KEY INSIGHTS:
=============

1. BUILD-TIME IMPACT:
   - More random points during build → higher recall but longer build time
   - 50pts: 97.36-97.88% recall, 400pts: 98.41-99.02% recall
   - Build time increases: 15.5s → 22.4s (45% increase)
   - Graph becomes slightly sparser with more random points

2. SEARCH-TIME STRATEGY IMPACT:
   - MEDOID search consistently achieves higher QPS (~35-40% faster)
   - Recall differences minimal: MEDOID vs RANDOM within 0.1-0.2%
   - MEDOID more efficient: fewer distance computations

3. OPTIMAL CONFIGURATION:
   - Best Quality: Build with 400 random points + MEDOID search
     → 99.00% recall@10, 6,869 QPS@L100
   - Best Balance: Build with 200 random points + MEDOID search
     → 98.67% recall@10, 6,358 QPS@L100, moderate 18.3s build
   - Fast Build: Build with 100 random points + MEDOID search
     → 98.37% recall@10, 7,224 QPS@L100, quick 16.9s build

4. CONCLUSION:
   - Build-time random points significantly impact final recall quality
   - Search-time strategy mainly affects QPS (MEDOID preferred)
   - Trade-off: Build time vs recall quality vs search performance
   - For production: 200-400 random points at build + MEDOID search
